What This Proves

💳 Payment Holds

Authorize, capture, or void funds — full double-entry ledger journaling. Same pattern as Stripe/Adyen payment lifecycle.

🔄 Idempotent Transfers

Send the same transfer twice — get the same result. Exactly-once guarantee via PostgreSQL idempotency keys, not application memory.

🛠 Operational Controls

Approvals, reconciliation, outbox dead-letter recovery, partition maintenance — all with role-based access and audit trail.

📚 PostgreSQL Truth

Accounts, ledger, idempotency, approvals, and audit live in PostgreSQL. Redis is non-authoritative acceleration. Kafka is async transport.

Architecture Decision

PostgreSQL ← Ledger · Accounts · Idempotency · Audit · Approvals
Redis ← Rate limiting · Idempotency replay cache (non-authoritative)
Kafka ← Event projection · Read models (optional in showcase)

3-Minute Walkthrough

  1. Open the Dashboard
  2. Login as demo_admin / demo_admin
  3. Click Initialize Demo Data (idempotent — safe to run repeatedly)
  4. Run Authorize Hold to reserve funds
  5. Run Capture Hold to settle the payment
  6. Run Internal Transfer with an Idempotency-Key header
  7. Replay the same transfer with the same key — returns the original result (exactly-once)
